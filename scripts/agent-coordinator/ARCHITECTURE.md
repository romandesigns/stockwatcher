## Threat model and lifecycle

Only an operator-authorized, scope/expiry/task-hash-bound preservation_inventory task is executable. A grant is a trusted host attestation of the owner's explicit chat instruction, not an agent-authored GitHub comment. Agents cannot issue grants. High-risk kinds have no handler; there is no approval flag that enables production/trading/restoration. Arbitrary issue prose, model output and reports are data. Initial task source is Issue #64, pinned in evidence; continuous discovery of arbitrary new issues is deliberately excluded.

SQLite WAL + FULL synchronous is the durable queue/journal/outbox. A single worker owns a renewable fenced lease. Every transition stores a complete task snapshot with source commit, artifact hashes and previous-event hash in one transaction. Startup verifies journal and materialized state. GitHub is an external audit anchor: exact marker/body/account read-back, existing comment reconciliation after ambiguous POST, fail on edited/deleted/duplicate receipts. No transition past a stage without its GitHub acknowledgement.

In-flight planning/review without durable completion fails closed after a crash. Execution records a durable intent before opening the fixed read-only tool; a receipt committed before a crash is recovered without rerunning the action. An intent without a receipt is ambiguous and blocks; expiry never silently requeues it. Rejected review routes to Codex at most twice; attempts remain separate artifacts. STOP is checked during subprocess execution and before side effects. A host restart never auto-enables the worker. No scheduled task or cloud service is created.

Separate C: detached worktrees per task; one worker (stronger than one per agent). Child sessions are fresh. Codex emits a schema-limited declarative plan with read-only sandbox/no tools; Claude reviews the exact plan hash with no tools; Claude executor receives only a fixed local inventory MCP tool. No model-selected shell commands, paths, URLs or executable code. Controller Git commands and PowerShell scheduler query are literal trusted code. Read-only reports are limited to explicit G: paths and small metadata, never .swa/tar payloads, J:, I:, frozen X1 inputs, or production service commands.

Limits: 180 s/agent; 20 min/task; max two remediation retries; 600 KB/agent output; 2 GiB free-space floor; 20 queued tasks; one approved run in the supervised test. Credentials remain in existing stores. Logs remain local and redact known token formats. Memory/CPU are bounded indirectly by one process and input/output/time limits; no claim of an OS job-object memory cap. Record that as a gap for broader deployment.

Independent review remediation: supervised workers always stop at an empty/terminal queue. A durable GitHub POST intent prevents duplicate posting even if comment-list visibility lags. The fixed MCP server has no GitHub adapter: it checks controller-verified local receipt hashes, while the controller performs remote validation immediately before launch and before the next transition. Git/source checks run outside SQLite write transactions. Expired grants/deadlines halt with last_error and remain non-executable until operator reconciliation; they are not automatically renewed.
